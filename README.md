# LUX — Tarot Waitlist

A minimal, magical, mobile-first landing page for **LUX**, a tarot reading service. Visitors leave their email to join the waitlist. Built as a pure static site (HTML/CSS/JS, no build step) and deployed on GitHub Pages.

**Live:** https://www.albertovaldesrey.com/tarot-web/ (GitHub Pages project site; `ledsav.github.io/tarot-web/` redirects there)

## Features

- Mobile-first, responsive layout: a title-page hero, "how a reading works", and the in-person waitlist; the reading page lays the turned card and its text out as a two-page spread on wide screens
- Animated "parting mist" entrance — smoke clouds drift away to reveal the page
- Staggered content reveal and a red-gloved arm rising with fanned tarot cards
- Editorial typography: Cormorant Garamond (display), EB Garamond (text), Cormorant SC (labels)
- The Lit X logo and favicon set, in `design/logo/`
- Email capture wired to a Google Sheet via a Google Apps Script webhook
- Respects `prefers-reduced-motion`

## Running Locally

No build step and no dependencies. Needs Python 3 to serve it and Node 20 (tested on 20.20) for the tests.

```bash
git clone https://github.com/Ledsav/tarot-web.git
cd tarot-web
npm start        # python -m http.server 8000, then visit http://localhost:8000
npm test         # node --test test/
```

Serve it rather than opening `index.html` directly, so the ES modules, `reading/` and fetch behave like production. In VS Code, *Setup (fresh clone)* checks the tools and runs the tests; *Dev* starts the server.

## Email Backend

Submissions are sent from `main.js` to a Google Apps Script web app (`SHEETS_ENDPOINT`), which appends each email as a row in a Google Sheet. The live waitlist sheet, and the Apps Script bound to it (`docs/apps-script/Code.gs`), live in Alberto's Google account, not in this repo; the `/exec` URL is hardcoded in `main.js` and `reading.js`.

The request uses `mode: 'no-cors'`, so the browser cannot read the response — the UI always shows success after the request fires. The endpoint URL is public by design; it only accepts POSTs that append a row.

To point at your own sheet:

1. Create a Google Sheet.
2. **Extensions → Apps Script**, paste `docs/apps-script/Code.gs` (it handles both the waitlist and the readings).
3. Follow `docs/apps-script/README.md`: add the `GROQ_API_KEY` Script Property, then **Deploy → New deployment → Web app**, access "Anyone", and copy the `/exec` URL.
4. Replace `SHEETS_ENDPOINT` at the top of `main.js` and `GROQ_ENDPOINT` at the top of `reading.js` (same URL).

## Tarot Reading (AI)

`reading/index.html` (served at `/reading/`) is an interactive 3-card (Past / Present / Future) reading. The 78-card
deck lives in `deck.js`; draw logic is in `draw.js` (unit-tested with `node --test test/`).
Readings are generated by Groq (`llama-3.3-70b-versatile`) through the same Google Apps Script
web app (`GROQ_ENDPOINT` in `reading.js`) — the API key is the `GROQ_API_KEY` Script Property
and never reaches the browser.
Setup steps are in `docs/apps-script/README.md`. Ambient music and a mute toggle use the
built-in HTML5 `<audio>` element.

The proxy endpoint is public and spends the free Groq quota, so `Code.gs` throttles globally
(10 readings/minute, 80/day; Apps Script can't see caller IPs). When a cap is hit the page
falls back to the curated card meanings in `deck.js`.

## Deployment

Hosted on GitHub Pages from the `main` branch root. Every push to `main` redeploys automatically:

```bash
git add -A
git commit -m "your message"
git push
```

Allow ~30–60s after a push, then hard-refresh (Ctrl+Shift+R) to bypass the browser cache.

To enable Pages the first time: **Settings → Pages → Source: Deploy from a branch → `main` / `(root)`**.
